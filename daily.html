1. Why are per-tool caps separate from the step cap?
An agent that may call read_file 30 times should still call send_email once. Caps are per risky tool, and budgets are per-tenant configurable.
⚡ Unlimited reads, one draft, zero sends.

2. Name the seven ways an agent loop should be able to end.
Model declares done, deterministic goal check, budget exhaustion, no-progress detection, error threshold, human interrupt or approval, external cancellation. A production loop needs all seven.
⚡ They're not alternatives.

3. State the asymmetry that drives memory write policy.
A missing memory produces a slightly worse answer. A wrong memory produces a confidently wrong answer, forever, in every future session, retrieved and stated as fact.
⚡ Writes need a higher bar than reads. Most teams invert it.

4. Approval bypass rate — exact numerator and denominator.
Actions taken without required approval / actions requiring approval. Target 0%. It is the cheapest deterministic gate for an agent that acts.
⚡ One bypass in a quarter is still a fail

🥊 tier 2 · staff — Design the cache stack for a copilot where a stale answer causes a customer outage
The support copilot answers questions like why is my tunnel flapping using runbooks plus live device state. Cost is $0.31 per ticket and the team wants it halved. The complication: last month a semantically cached answer told an engineer a threshold that had changed in the config two days earlier, and the site was black-holed for 20 minutes. Product now says any cache that can serve a stale operational fact is off the table. You are asked for the layered cache design, what each layer is allowed to cache, and how invalidation actually works.
  1. Split the question space first: stable knowledge is cacheable, live operational state is not.
  2. Start with the prompt cache — stable prefix first, variable last — highest hit rate, lowest risk.
  3. Add the embedding cache keyed by content hash plus model id; it is deterministic and cannot go stale.
  4. Tool result cache with per-tool TTL: seconds for live metrics, minutes for config snapshots, forever for historical events.
  5. Response cache only for context-free queries; tag entries with tenant and invalidate on tenant config change.
  6. Semantic cache last, and only with provenance: entry maps to source doc ids and evicts when they change.
  7. Every key carries tenant_id — a cross-tenant cache hit is a security incident, not a cost win.
  8. Sample cache hits continuously for human audit; without sampling you learn from the customer.
  9. One invalidation event bus: any knowledge artifact publishes changed, all subscribed layers evict.

Numbers

  • Layer hit rates and savings: L3 prompt 80-95% at 90% input discount; L5 embedding 60-90% at 100%; L4 tool 40-70%; L2 semantic 25-40%; L1 result 5-15% (issue 003, §5).
  • Tightening the semantic threshold from 0.95 to 0.98 cuts hit rate 35% to 15% and savings from $8K to $3.5K a month (issue 003, §12).
  • Embedding cache math: 1K tokens costs ~$0.0001, so $500/year becomes $50K/year if you re-embed 100 docs per query — a 100x sink (issue 004, §5).
  • Prompt cache TTL is 5-60 minutes, so low-traffic features need a warmer calling the prefix every 4 minutes (issue 004, §5).

Traps

  • Quoting a semantic hit rate as the win without naming the invalidation model — that is the incident you just had.
  • Caching answers that embed live state at all; time-bound aggressively or serve uncached for freshness.
  • Omitting tenant_id from a key to raise the hit rate.
  • Shipping the semantic layer before the response and tool layers work — it is a v2, not a v1.

Follow-ups

  • Finance wants the $8K a month back. What do you tell them?
    We keep the savings that cannot be wrong: prompt, embedding, tool result and context-free response caching already move the bill more than the semantic layer did. The semantic layer returns once entries carry source doc ids and evict on document change — three weeks of work.
  • The semantic cache worked fine at 1,000 queries a day. Why did it break at 100,000?
    The query distribution widened. More near-misses cross a fixed similarity threshold, so false positives scale faster than traffic. Mitigations are per-tenant namespaces, progressive threshold tightening as volume grows, and continuous sampling of hits for audit.
  • Where does the cache stack stop helping cost?
    When the cheapest lever is structural, not cached: eliminate the call, gate scope at ingress, route tiers. Model routing is a 5-20x swing versus caching's 50-90% on input tokens only.
