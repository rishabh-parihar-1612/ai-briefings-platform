The Agent System Stack

Six layers, one symptom-to-layer map · agent-stack

supportinghigh confidence2026-09-10

Hook

"The agent is unreliable" isn't a bug report — it's five different bugs hiding in one sentence, and each lives in a different layer of six.

Mental model

A model reasons; an agent is the system that gives that reasoning a world to act in, a boundary it cannot cross, and evidence the outcome happened. The stack is a debugging tool, not a taxonomy.

Decide

Use when invest in the full stack
  • Task needs more than one model call or touches more than one document
  • Any write action reaches a real system of record
  • Debugging "it's unreliable" reports already wastes real time
Skip when stay at prompt + context
  • A single model call in a known format solves it
  • Steps and order are fully known in advance — use a workflow
  • No production trace has justified going past layer two yet

Aryaka

Aryaka's network-diagnosis agent maps onto all six layers: prompt (evidence-backed diagnosis, schema-validated), context (filter-then-rank over historical cases, never the whole corpus), tools (seven read-only sources, one approval-routed write), harness (read-scoped identity, one kill switch), loop (8 actions or 12 minutes, four exits), eval (~200 frozen tickets, deterministic grader, five trials). When a NOC engineer reports "the diagnosis was wrong," the first move isn't a prompt edit — it's pulling the trace and classifying it into one of the six symptom buckets, because "wrong" from stale context and "wrong" from a bad tool argument get fixed in completely different places.

Say this

"Unreliable" isn't a bug report. Give me a trace and I'll give you a layer — six of them, and each symptom maps to exactly one.

Trap

Answering an architecture question with a framework name and a box diagram instead of six responsibilities. The tell: every follow-up — what can it touch, when does it stop — has nowhere to attach in that diagram.

Probe

A user reports "the agent is unreliable." What's your first move?
Show answer

Refuse the word — pull 20 failed traces and classify each into one of six layers. The distribution is usually lopsided and almost never the layer the team assumed; only then pick a fix.

Two tools, get_device_status and get_device_config, both described as "returns device information." What's actually broken?
Show answer

Nothing throws an error — the agent silently picks whichever description reads as more relevant, and quality degrades with no visible failure. Overlapping tool descriptions are a contract bug, not a model limitation.

When does an agent legitimately need memory added?
Show answer

When tasks genuinely span sessions — not because the demo would feel nicer — and only once you can name who corrects a wrong memory. Without a corrector, engineers become the correction path via manual database edits.
