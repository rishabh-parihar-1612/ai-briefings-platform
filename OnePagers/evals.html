Agent Evaluation

The reliability contract · evals

corehigh confidence2026-09-03

Hook

Reliability = observability + evals. Traces are not the safety net — they are the input. You cannot evaluate what you did not store.

Mental model

QA for a system that answers differently every run. So the evidence is the trace of actions plus the resulting environment state, never the final message. Lower-layer quality never guarantees upper-layer quality.

Decide

Use when a suite is worth its cost
  • Output reaches a customer, or any write action exists
  • Two prompts or models must be compared objectively
  • Regression across releases would be invisible otherwise
Skip when defer, do not fake it
  • The prototype still changes shape weekly
  • No domain expert is available to author cases
  • Success has no checkable definition yet

Aryaka

Support-triage agent. Ingests a ticket, retrieves the runbook, queries device telemetry and the change DB, drafts an RCA, and can open a carrier ticket behind an approval gate.

Schema first: ticket_id, prompt version, retrieved chunk ids and text, every tool call with arguments and full response, the draft, and whether a human edited before sending.

Golden set: 40 closed tickets picked by a senior NetDevOps engineer, biased toward the ones misdiagnosed the first time — easy tickets teach nothing.

Gate: zero tolerance on get_approval before open_carrier_ticket; groundedness and relevancy thresholded with no-regression against last release; edit-rate-before-send tracked but not gated.

What breaks: seeded telemetry fixtures with no reset between trials.

Say this

Two things, in order. We record every tool the system called and why. Then we grade it against cases our own experts wrote — and the pass bar is not ours to move.

Trap

Grading the final message. The tell: your suite scores responses, so an agent that skipped the identity check and then wrote a fluent RCA passes. Grade the trace and the environment state.

Probe

Your suite passes at 92% and the agent still fails in production. First hypothesis?
Show answer

Case mix, not case quality — the suite has the right cases in the wrong proportions. Re-weight by production intent frequency before touching the agent. Then: judge drift, environment mismatch, and metrics that never measured the failing dimension.

Why is blocked a first-class trial outcome alongside pass and fail?
Show answer

Without it, environment breakage counts as agent failure and the suite reports a capability regression that never happened. Its sibling field, human intervention, is what tells you whether the autonomy is real.

You can compute groundedness for last week's run — or you cannot. What decided it?
Show answer

The trace schema, decided before the first eval ran. Groundedness needs query + response + system prompt + context; if the retrieved chunks and tool responses were not stored, every past run is permanently ungradeable. Schema design is an eval decision.
