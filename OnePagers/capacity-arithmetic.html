Arithmetic-First System Design

A wrong number beats no number at all · capacity-arithmetic

supportingmixed confidence2026-09-10

Hook

Wrong number stated confidently beats no numbers — the interviewer is grading the arithmetic habit, not the answer key.

Mental model

Every architecture decision must trace back to a number. Run requests → QPS → tokens → cost → latency before naming any component past a single prompt call, then escalate only when the numbers demand it.

Decide

Use when
  • Answering any AI system-design question before naming a single component
  • A team proposes an advanced architecture without a stated number behind it
  • Debugging a RAG system's degraded answers
Skip when
  • The system is a rung-1 prompt call with no retrieval, tools, or fine-tuning need
  • Numbers are already run and documented; re-deriving them is wasted motion
  • The question is genuinely non-functional (UI, data residency) and arithmetic won't answer it

Aryaka

Aryaka's NetOps support desk: hundreds of engineers, not millions of consumers — an immediate signal this is a different scale problem than a consumer bank chatbot. Device configs and incident runbooks change continuously, so RAG, not fine-tuning, for the same structural reason as the bank's weekly policy updates. Running the arithmetic first (an Aryaka-scale estimate: ~$150–250/day at 10,000 requests/day) shows a three-tier router is very likely solving a cost problem this system doesn't actually have.

Say this

I ran the numbers back through the actual denominator and found I was 50% over budget, not under — that's the arithmetic habit the interview is grading, not whether my first number was right.

Trap

Opening a system-design answer by naming a vector database, a reranker, and an agent framework in one breath. The tell: no number ran yet, so every component is a taste claim, and the interviewer can only counter with taste.

Probe

You're asked to design an assistant with a $0.02-per-conversation target. Your routing split brings cost to $6,000/day across 200,000 conversations. Is that under budget?
Show answer

No — $6,000 ÷ 200,000 = $0.03/conversation, 50% over budget. The naive read conflates the conversation count with the higher request count used earlier in the token arithmetic; catching that division error yourself, out loud, is the stronger signal.

A stakeholder proposes fine-tuning weekly since "policies change weekly." What's wrong with that plan?
Show answer

Fine-tuning updates style/behavior, not reliably-recallable facts, on a days-to-weeks retraining cycle — a fine-tuned model chasing weekly changes is perpetually one cycle stale. RAG's reindexing cycle can actually match that frequency; fine-tuning's retraining cycle can't.

RAG answers have degraded in production. What do you check first?
Show answer

Top-down through the funnel, never the prompt first: is the index stale? Are the top-50 candidates actually relevant? Is the reranker improving on that set, or is chunking feeding it garbage? Only once all three are clean does the prompt or model become a plausible suspect.
