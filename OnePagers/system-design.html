Agentic AI System Design

Distributed system, nondeterministic control path · system-design

corehigh confidence2026-09-10

Hook

An agentic system is a distributed system with a nondeterministic component in the control path — that third clause is the one people underweight.

Mental model

Autonomy is a dial of delegated control, not a category. Every notch traded for capability costs determinism. Choose the leftmost point on the spectrum that solves the problem — spend the debugging budget only where nondeterminism is required.

Decide

Use when build the full architecture
  • Task genuinely needs multi-step judgment under real ambiguity
  • An action is WRITE_HIGH or DESTRUCTIVE class
  • More than one team will own agents sharing this system
Skip when stay simple
  • A deterministic pipeline already solves it end to end
  • Only read-only, advisory actions are in scope today
  • No production trace has yet proven a specific failure

Aryaka

A NOC triage agent for Aryaka's SD-WAN/SASE estate: dedupe/enrich by rule (kills 60–80% of alert volume for free), a small model classifies severity, a capped investigation sub-loop (max 8 tool calls, $0.40, 45s) gathers read-only evidence, then one frontier call proposes a root-cause hypothesis with confidence. Deterministic code validates the hypothesis's runbook references before a ticket comment posts — WRITE_LOW, rate-limited, idempotent. v1 is advisory only: no config pushes, no remediation. That single scoping decision is what lets it ship in weeks instead of quarters — an estimated 4–6 model calls per triage, not 15, because T0 rules do most of the work.

Say this

The model proposes; deterministic code disposes. Every business rule lives in code, never a prompt — a prompt is a suggestion to a probabilistic system an attacker can address directly.

Trap

Shipping a six-agent decomposition because the org chart has six teams. The tell: if you can draw the system as a straight line, it isn't multi-agent — it's a pipeline you made expensive, and you're paying ~15× tokens for the privilege.

Probe

A demo works flawlessly. Stakeholders want to ship it as-is next week. What's your answer?
Show answer

Name which of the five demo-to-production gaps it hasn't crossed: input distribution, failure surface, scale economics, consequence, time. A demo proves the model can do the task; it proves nothing about typos, API failures, real cost at volume, or 18 months of drift underneath it.

Your agent's system prompt says "never refund over $500 without approval." Is that control sufficient?
Show answer

No — a prompt is a suggestion a probabilistic system can be talked out of; an attacker addresses it directly. It has to be a code check (if amount > 500: require_approval()), because Replit, Chevrolet of Watsonville, and Air Canada are three companies whose public incidents all trace back to exactly this gap: a rule that lived in language instead of code.

Approval requests on your one write tool are granted in under two seconds, every time. What's actually happening?
Show answer

The gate is decorative — you're running effectively-unapproved writes with a compliance artifact attached (>95% approval rate is the threshold). Fix: narrow the approval class with deterministic auto-approve bands so the remaining approvals are rare and real, not retrain the approvers to read more carefully.
