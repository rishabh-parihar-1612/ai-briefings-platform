The Agent Testing Pyramid

Unit-test the harness, evaluate the model · evals › testing-pyramid

corehigh confidence2026-09-10

Hook

"We have evals" is only half a testing strategy — a broken if-statement can look exactly like model flakiness.

Mental model

Test deterministic harness code with mocked-model unit tests; evaluate probabilistic model behavior with evals — component, seam, end-to-end, then adversarial, with every production failure converted into a permanent regression case.

Anatomy

PieceDoesFails when
Harness unit testsMock the model, assert deterministic control: budgets, retries, approvalsLoop bugs get "fixed" by prompt-tuning instead of unit-testing the code
Component evalsRetrieval, extraction, classification, tool-selection, generation evaluatedOnly the final answer is graded, missing which capability actually failed
Seam evalsDoes component B correctly interpret and use component A's outputEvery component passes standalone while the combination still fails
E2E task successStructured, multi-field success criteria, not "the response sounds good"Success judged by fluency instead of a checklist of concrete facts
Adversarial suiteInjection, malformed tool output, stale data, budget exhaustionOnly a happy-path dataset exists; production is the first adversarial test
Deterministic replay regressionOne-click: production failure trace → permanent regression caseConverting a failure into a test case takes 20 minutes, so it rarely happens

Numbers

6 layersHarness unit → component → seam → E2E → adversarial → replay regressionOne metric or test type never covers all of them

Decide

Use when
  • An agent has a harness/runtime (loops, budgets, state, approvals) separate from model calls
  • "The AI seems flaky" is being diagnosed with prompt changes instead of code review
  • Production failures aren't yet converted into a growing regression suite
Skip when
  • The system is a single stateless model call with no orchestration to unit-test
  • Component-level evals already fully cover the task (rare — check for seams first)
  • No production traffic exists yet to mine for adversarial or regression cases

Aryaka

Benji's harness tests cover scheduler behavior, retry logic, worker limits, Salesforce update gating, and Teams-notification approval workflows — all with a scripted fake model, no LLM call needed. Component evals separately check signal extraction (M&A, traffic decline, packet loss), signal scoring against the configured formula, and retrieval correctness. 2 seam evals check the telemetry-to-signal-detector and analyzer-to-recommendation handoffs specifically. And every production trace where a health label was wrong becomes, in one click, a permanent regression case run on every future release.

Say this

Test deterministic code with software-engineering tests, and evaluate probabilistic behavior with evals. A broken if-statement is a software bug, not an AI-quality problem, and a prompt change never fixes it.

Trap

Treating "we have evals" as a complete testing strategy. The tell: a harness bug (a budget miscounted, an approval gate skipped) gets diagnosed as "the model is flaky," and someone tunes a prompt that was never the problem.

Probe

Your agent occasionally skips a required approval gate before a high-risk action. How do you test for this without needing a real, unpredictable model?
Show answer

Mock the model with scripted outputs, then assert deterministic harness behavior: approval requested, tool not executed, state moved to WAITING_FOR_APPROVAL. Ordinary software testing — no LLM call needed — catches exactly the bug class that looks like "AI flakiness" but isn't.

All your component-level evals pass individually, but the end-to-end task still fails. What are you missing?
Show answer

Seam evals — the interaction between components. Retrieval can correctly return a fact and planning can pass its own tests, while the seam still fails if planning misinterprets that fact. Test whether component B correctly uses component A's actual output, not each in isolation.

How do you keep an eval suite from going stale as production evolves?
Show answer

Make the path from a production failure to a permanent regression case nearly free — one click from a captured trace, not a 20-minute manual fixture-building process. If conversion is expensive, the eval set stops growing from real failures.
