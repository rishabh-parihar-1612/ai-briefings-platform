Agent Harness

The model is rented, the harness is owned · harness

corehigh confidence2026-09-03

Hook

The model never touches the world. It didn't choose its permissions, define its tools, build its workspace, keep its task state, or verify its result — the harness owns all five.

Mental model

Two agents on the same model are different systems, not differently-prompted versions of one. The model is rented; the harness is owned. A better model raises the ceiling — the harness decides where you sit under it.

Decide

Use when build the component out
  • The agent is about to get its first write action
  • Work spans more than one context window or session
  • A postmortem blames the model and the environment is suspect
Skip when resist the machinery
  • No observed failure is asking for this component
  • One agent, three tools and one verifier still untested
  • A framework install is being offered as the design

Aryaka

The diagnosis harness. Seven read tools (mutates: false) plus one approval-routed write — post the diagnosis. Read scopes ambient; write released per approval. Workspace: a tenant-scoped read replica, no shell, query ranges capped so a malformed range can't pull a week of the estate.

Trigger: a tunnel-flap ticket. System: device IDs validated against inventory first, so a hallucinated ID fails at the harness, not the vendor API; budget 8 actions/12 min. Human sees: the drafted comment and its cited observations. Breaks when: rollback — deleting the posted comment — has never actually been executed.

Assumption: ~10GB traces/year at 200 runs/day. The approval path caps throughput.

Say this

Two agents on the same model are different systems. A better model raises the ceiling; the harness decides where we sit under it — and enforcement lives in the runtime, never in the prompt.

Trap

Naming a framework as the harness design. The tell: asked for the five artifacts, the team shows you a dependency file. Frameworks supply scaffolding for all five responsibilities and decisions for none of them.

Probe

Your agent's instructions say "never deploy." What is still missing?
Show answer

Runtime enforcement. Replit, July 2025 — production database deleted during a stated code freeze, because the instruction existed in English and the boundary did not exist in the runtime. Every tool declares mutates, the harness routes on that flag, and write scopes are released per approved action rather than held ambient. The model never decides what feels risky.

The process restarted mid-task. Which store does resume read?
Show answer

Task state — goal, constraints, findings with confidence, tried-and-failed, next safe action. Never the transcript: a polished transcript preserves intentions and loses the identifiers, check results and permission decisions the next operator needs. Then re-verify anything time-sensitive, because observations go stale across the interruption.

Approvals on your one write tool are granted in about two seconds. Diagnosis and fix?
Show answer

The control is decorative — you are running unapproved writes with a compliance artifact attached. The fix is not retraining approvers, it is narrowing the approval class: approve by exception on an action class that has a demonstrated rollback, plus an escalation-quality number. Same instinct as testing the kill switch mid-write rather than between runs.
