Business Context Over Technique

Name the decision before touching the model · interview-technique

supportinghigh confidence2026-09-10

Hook

Technical correctness and business-context framing are scored on separate axes — you can nail the first and still lose the interview on the second.

Mental model

Before executing a requested build, state what decision it serves and whether the target is well-posed. When asked "why X over Y," answer the specific delta, not how each works in general.

Decide

Use when
  • Given an open-ended build/design task in an interview or design review
  • Asked "why X over Y" and tempted to explain how each works in general
  • A prediction/classification target feels intuitively incomplete
Skip when
  • The task is a closed, well-specified question with no framing ambiguity
  • The comparative question already specifies the exact axis to compare on

Aryaka

Asked to design an anomaly-detection model for SD-WAN tunnel latency, the technical-first answer picks isolation-forest-vs-LSTM and explains each of the 2 approaches. The stronger answer asks first what action the anomaly flag triggers (automated failover tolerates far fewer false positives than a dashboard signal) and whether latency alone is the right target versus latency-plus-packet-loss-plus-jitter — the same latitude-without-longitude problem the source interview's candidate eventually recognized. Only then: isolation forest over LSTM specifically because labeled anomaly data is scarce, not a recitation of how either algorithm works.

Say this

Before touching technique, state what decision the task's output actually serves, and whether the target as given is well-posed — that's the difference between a correct answer and the answer that gets used.

Trap

Answering "why X over Y" by explaining how X and Y each work internally. The tell: the interviewer prompts twice before you volunteer the actual framing objection — a stronger candidate raises it unprompted, in the first thirty seconds.

Probe

You're asked to build a model predicting a single variable from a dataset, and complete it correctly. What might still be missing from a strong answer?
Show answer

Whether the target itself is well-posed — a single variable in isolation may have no clean relationship to the rest of the data, the same way many single-metric targets are half of what's actually needed. Naming that unprompted is the stronger signal than the model's accuracy.

Asked "why isolation forest over an LSTM for this anomaly detector," what's the weaker answer and what's the stronger one?
Show answer

Weaker: explaining how isolation forest and LSTMs each work in general. Stronger: naming the specific delta for this case — labeled anomaly data is scarce, and isolation forest doesn't need it, while an LSTM would.

An interviewer pushes back twice before you acknowledge a task's framing might be wrong. How does that read?
Show answer

As the instinct not yet being automatic. The target is naming the framing problem unprompted, in the first moment of an open-ended task — surfacing it only after being pushed reads as competent but not yet senior.
