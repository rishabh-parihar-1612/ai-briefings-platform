Memory Retrieval

Four ways, and the boring one wins · memory › retrieval

corehigh confidence2026-09-04

Hook

Keyword retrieval fails silently on surface-form mismatch. English memory, Chinese query: 10.3 seconds, no result, no error — indistinguishable from having no memory at all.

Mental model

Four retrieval methods, and production is a hybrid: keyword for identifiers, vector for prose, preload for the short and mandatory, graph only where the edge is the fact. Similarity is not relevance, and it is definitely not truth.

Decide

Use when reach for the method
  • Preload: short, mandatory, and omission is a safety failure
  • Keyword: the query carries an exact identifier
  • Graph: the question is about relationships between entities
Skip when the method is wrong here
  • Vector-only for facts with a schema and a correct answer
  • Graph for attribute questions like "what is this SLA"
  • Keyword-only, with no path for a paraphrased query

Aryaka

The lexical failure, concretely. A customer writes "the tunnel keeps dropping." The stored memory says "IPsec SA renegotiation flap." Zero token overlap. The keyword path returns empty, and the agent reports it has no record — while the fact is sitting in the store.

Triage order: direct store lookup versus retrieval lookup. Present but not in the top-k is a ranking or filter bug; absent is a write-path bug. Those are different teams, and getting it wrong costs a week.

The eval that would have caught it: take 50 real memories, have a model paraphrase each into how a customer would actually ask, then measure recall. Most retrieval evals use queries written by whoever wrote the memory, which tests nothing — they share vocabulary by construction.

Say this

Hybrid, for a measured reason rather than a stylistic one: keyword for identifiers, vector for prose, and a tested fallback when keyword returns zero rows — because that failure is silent.

Trap

Tuning k or the similarity threshold. The tell: you reached for a knob before counting distinct facts in the top five — and a bigger k mostly adds plausible-but-wrong neighbours as the corpus grows.

Probe

What is the single argument for graph memory, and what does it cost?
Show answer

The edge is the fact. In a graph built from a conversation, an edge labelled "revealed ending of" connects Tom Holland to his next film — two flat facts ("Tom Holland exists", "a film exists") mean nothing. The cost is on write: building nodes, edges and validity intervals is model work per fact, on ingest, which is why one product never finished seeding. Async write path, and recall evals — a graph visualisation is persuasive and its failures are pretty.

Why is a no-memory control group the first thing you build in a memory benchmark?
Show answer

Without it you cannot separate "the memory retrieved the fact" from "the model guessed plausibly." In the race done properly, the control correctly answered "I have no record of that" every time — which is exactly the behaviour you need to distinguish from. Then make the fixture adversarial: an entity plus an event, a fact superseded mid-run, a relationship question, and a query in a different surface form from the stored memory.

Where do mutable facts belong, and why not in embeddings?
Show answer

In structured rows, with the vector index over descriptions rather than over the facts. The deciding constraint is update and delete semantics, not recall quality: correcting an embedded fact means finding and re-embedding every derived chunk, while a structured row is one UPDATE. Teams that put plan tier, contacts or topology into embeddings discover this on the first correction.
