The Harness Contract

UI work is context engineering · deep-agents

supportinghigh confidence2026-09-10

Hook

Anything the harness pulls out of the messages list must stay reachable to the model through tools — or it's invisible, permanently. UI work is context engineering.

Mental model

Three layers: in the messages list (always seen), offloaded (reachable via pointer+tools), or outside both (invisible, forever). Every rendered pixel either has a model-reachable representation, or it doesn't exist to the agent.

Anatomy

Decide

Use when
  • Any artifact is rendered to the user outside the plain chat message
  • Users will plausibly ask a follow-up question about what they're looking at
  • More than one process (sub-agent, front end, main agent) touches the same data
Skip when
  • Every output is a short chat reply — nothing else is ever rendered
  • The artifact is disposable and no follow-up question is expected
  • Only one process ever touches the data — no multi-party visibility problem exists

Aryaka

Aryaka's network-analysis agent ranks 800 sites by tunnel-availability drop below 99.5%. The conversation and a small region-summary chart stay in the messages list. The full ranked list is written by a sub-agent to analysis/sites-ranked.jsonl; the front end renders straight from that file via API while the main agent reads it in chunks. When a NOC lead asks "why is Bangalore ranked above Pune," the main agent reads the relevant chunk and answers, because the file — not a description of it — is the shared reality all three parties address by one path.

Say this

UI work is context engineering. If a rendered artifact has no representation the model can reach, you've built a shared reality the model isn't part of — and the user will assume it is.

Trap

Patching an "agent can't explain the chart" bug with a text summary added to the context. The tell: "regenerate this and move three things right" still fails — the model has a description of an artifact it can't actually modify.

Probe

A user asks the agent "why is that company on the left?" about a chart it just rendered, and the agent can't answer. What's the actual bug?
Show answer

A harness-contract violation — the chart exists only in the front end's rendering, with no representation in the messages list or harness-offloaded storage. It's not a prompt bug; the fix depends on the artifact's size (delimiter tag, ID+tools, or shared file system).

How do you decide between a delimiter tag, an ID-plus-tools, and a shared file system for a given artifact?
Show answer

By size and number of writers. Small, single-author artifacts go inline with a delimiter. Large single-source artifacts get an ID plus status/fetch tools. Multiple processes writing and reading the same data need a shared file system as the actual integration bus.

What's the tell that a design has a harness-contract violation before a user ever files a complaint?
Show answer

Catching yourself writing a prompt instruction like "trust that this is being rendered, don't respond" — a load-bearing lie standing in for a missing model-reachable representation. It fails on the first follow-up question.
