Code Mode vs Tool Calling

A training-data win, a permission-surface cost · mcp › code-mode

corehigh confidence2026-09-10

Hook

Code mode helps because models write real code better than they emit tool-call JSON — but composing multi-step chains blind only works when every intermediate shape is genuinely fixed.

Mental model

Presenting MCP tools as a typed code interface lets the model write and execute calling code instead of emitting tool-call JSON — a training-data advantage that also widens the permission surface the harness has to guard.

Decide

Use when
  • An agent selects among many or complex tools where JSON-based calling degrades
  • Every intermediate output in a composed chain has a genuinely fixed, typed shape
  • A sandbox/isolate execution environment exists or can be built for generated code
Skip when
  • No sandboxing story exists yet for arbitrary generated code
  • Chain intermediates come from third-party or loosely-typed sources
  • The tool set is small enough that conventional tool-calling isn't visibly straining

Aryaka

Aryaka's NetOps triage agent composes tunnel-status → region-lookup → carrier-feed checks. The first two are internal, versioned Aryaka services with fixed schemas — safe to compose as one code-mode block. The carrier-status feed is third-party with a variable response shape, so that hop stays outside the composed block, or the model is shown the carrier feed's raw response afterward to flag anything unexpected. The harness scopes the composed code read-only across all 3 systems regardless of what the generated code asks for.

Say this

Code mode is a training-data argument, not a protocol argument — composing a multi-step chain blind only holds up when every intermediate shape is genuinely fixed, which most integrations aren't.

Trap

Adopting code mode as a prompting change without touching the permission model. The tell: generated code is a larger blast radius than a validated tool call, and Cloudflare's own production version runs it inside sandboxed isolates, not on trust.

Probe

Should you move an agent with 15+ tools from tool-calling to code mode?
Show answer

For single-hop tool selection, yes — a straightforward, training-data-backed win. For multi-step chains, only once you've audited which tool outputs have genuinely fixed shapes; composing blind on a variable one breaks silently the first time it returns the unexpected.

What changes about your security review once an agent adopts code mode?
Show answer

The review point moves from "validate this one call against a schema" to "sandbox the execution environment itself" — generated code is the executable artifact now, so credentials need scoping to the sandbox's worst case, matching Cloudflare's own isolate-based implementation.

A composed code-mode chain calls a third-party API with an unpredictable response shape. What's the fix?
Show answer

Either keep that hop outside the composed block so the model can react to its actual response, or use speculative review — execute the full chain, then show the model every intermediate output afterward so it can flag anything it wouldn't have expected mid-execution.
